# Feature Specification: AppleUI 社区液态玻璃导航接入

**Created**: 2026-10-26  
**Status**: Draft  
**Input**: 用户要求：在已完成的“米饭好物”浅色购物页面上接入 `com.hm.appleui.hw` 社区液态玻璃，保留普通版与官方版，不重做业务页面；固定 2.1.0，先确认 ABI、SDK 和原生库加载条件；三套方案收在“我的 → 演示设置”；只用单个透镜作为底部导航材质层，商品列表不玻璃化；参数从 Blur 0、温和折射开始，关闭 ProUI 与 Vibrate，不申请振动权限；玻璃不得吞掉导航、滚动和购物袋事件；保持购物袋状态与全部业务交互。

## Overview

在现有“米饭好物”应用中增加第三种可验证的导航方案：社区 `com.hm.appleui.hw` 2.1.0 液态玻璃。社区方案只把底部导航胶囊作为单个玻璃透镜，透镜下方必须是本应用实时的商品内容；四个导航入口、选中态、购物袋角标和业务页面保持现状。普通导航与官方 HDS 导航继续保留，三套方案统一在“我的 → 演示设置”切换。

本特性的价值是验证社区原生液态玻璃在真实设备上的接入条件、采样表现和交互隔离，同时不牺牲现有购物、搜索、分类与购物袋流程。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 切换到社区液态玻璃导航 (Priority: P1)

用户打开“我的 → 演示设置”，选择“社区液态玻璃”，回到推荐页；底部导航胶囊呈现实时液态玻璃效果，玻璃下方能透出真实商品列表，四个导航图标、文字、选中态和购物袋数量仍正常显示和点击。

**Why this priority**: 这是本特性的核心交付；没有可选择的社区方案和真实可用的导航，就没有接入价值。

**Independent Test**: 只实现社区方案入口与单透镜导航，保持业务数据不变；在支持的 arm64 设备上选择社区方案，确认玻璃出现在底部导航位置且导航可点击。

**Acceptance Scenarios**:

1. **Given** 应用在支持的设备上启动，**When** 用户进入“我的 → 演示设置”并选择“社区液态玻璃”，**Then** 应用切换到社区导航，底部出现一个与普通/官方版位置接近的液态玻璃胶囊。
2. **Given** 社区导航已显示，**When** 用户查看推荐页并滚动商品列表，**Then** 玻璃内部反映的是当前可见的真实商品内容，不是预制纹理、固定动图或截图。
3. **Given** 社区导航已显示，**When** 用户点击四个入口、购物袋角标或商品按钮，**Then** 导航切换、购物袋和商品交互与普通/官方版一致，玻璃不阻断点击或滚动。

---

### User Story 2 - 业务页面与购物袋在三套方案间保持一致 (Priority: P1)

用户继续使用现有搜索、分类筛选、加入购物袋、数量增减和删除；在普通、官方、社区三套方案之间切换时，购物袋内容不会被清空、重复添加或丢失。

**Why this priority**: 接入新材质不能破坏已经完成的业务闭环；购物袋状态是跨方案一致性的核心证据。

**Independent Test**: 在任一方案下加入商品并修改数量，切换到另外两套方案，再回到购物袋核对商品、数量和合计。

**Acceptance Scenarios**:

1. **Given** 购物袋中有 2 件商品，**When** 用户从官方方案切换到社区方案，**Then** 购物袋仍为同样 2 件，数量、价格和合计不变。
2. **Given** 用户在社区方案下搜索或分类筛选，**When** 切换回普通或官方方案，**Then** 业务页面仍可用，未出现重复商品或状态重置。
3. **Given** 用户从社区方案离开再进入应用，**When** 重新打开页面，**Then** 导航和购物袋行为符合现有规则，不出现重复玻璃实例或重复商品。

---

### User Story 3 - 能力不足时准确说明，不伪造接入成功 (Priority: P2)

在不满足 ABI、SDK 或原生渲染条件的设备上，用户仍能使用普通/官方方案；社区方案必须明确显示不可用原因，不能把透明、黑块或降级效果标成“已接入成功”。

**Why this priority**: 社区库只提供 arm64-v8a 原生库，且依赖 OpenGL ES 3.0；错误地宣称成功会误导验收和后续文章。

**Independent Test**: 在非 arm64 或缺少渲染条件的设备上打开演示设置，确认社区入口的可用状态与说明；在支持设备上确认状态为可用。

**Acceptance Scenarios**:

1. **Given** 设备 ABI 不包含 arm64-v8a，**When** 用户查看演示设置，**Then** 社区方案显示不可用原因，不能被选中或伪装成玻璃效果。
2. **Given** 设备满足 arm64 和 API 20+，**When** 用户选择社区方案，**Then** 设置页显示实际库版本与单透镜能力，不显示“未接入”。
3. **Given** 原生渲染启动失败，**When** 用户查看页面和日志，**Then** 页面仍保留可用导航与业务操作，日志记录失败原因，最终报告不把该次运行标为成功。

---

### Edge Cases

- 设备旋转、窗口尺寸变化或安全区变化时，玻璃宽度与底部位置必须随导航胶囊重新布局，不能留下旧尺寸的透镜或错位采样。
- 应用进入后台再回到前台、页面重进、方案来回切换时，不能重复创建 AppleUI 实例，也不能让旧实例继续截帧。
- 商品列表滚动到末尾时，最后一件商品仍要完整出现在导航上方；玻璃不能遮住“加入”按钮或列表末尾。
- 搜索无结果、分类为空、购物袋为空时，玻璃仍保持同一位置和可点击导航，不显示与业务无关的技术说明。
- 浅色商品图和白色卡片经过透明玻璃时，图标和文字仍需可读；不得用覆盖大片商品内容的白色渐变或遮罩来换取可读性。
- 玻璃区域不能成为空效果层、不透明底板或包含自身的截图层；否则会出现黑块、青/品红自反馈或采样错位。
- 不支持 OpenGL ES 3.0、缺少 arm64 原生库或系统版本低于库要求时，必须保留普通/官方方案并给出准确失败说明。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 保留现有“普通导航”和“官方沉浸光感”两套方案，并新增第三套“社区液态玻璃”方案；三套方案统一在“我的 → 演示设置”中选择。
- **FR-002**: 社区方案 MUST 使用 `com.hm.appleui.hw` 2.1.0；如需更换版本，必须先说明原因并读取对应版本的 README，不能静默升级。
- **FR-003**: 社区方案 MUST 只创建一个 AppleUI 透镜，作为底部导航胶囊的材质层；商品列表、商品卡和页面背景不得整体玻璃化。
- **FR-004**: 社区导航 MUST 保留“推荐、分类、购物袋、我的”四个入口、现有图标体系、选中态、购物袋真实数量和全部点击行为。
- **FR-005**: 社区导航 MUST 在 AppleUI 透镜上方保留独立的导航点击层；透镜本身不承担导航点击，不得吞掉导航、页面滚动或购物袋按钮事件。
- **FR-006**: AppleUI 的采样目标 MUST 是透镜紧邻下方的真实业务内容层，且与透镜在屏幕上实际重叠；采样目标不得包含 AppleUI 自身，也不得是只有模糊/渐变效果、没有实际内容的空层或不透明底板。
- **FR-007**: 社区导航的透镜宽度、高度、圆角和底部位置 MUST 与现有悬浮导航保持接近；默认使用短边最大圆角形成胶囊，底部安全区和列表末尾留白必须保留。
- **FR-008**: 首轮参数 MUST 从 `Blur = 0`、温和折射开始；`ProUI` 和 `Vibrate` 必须关闭；不得新增振动权限，不得让整个导航栏被拖动或拉伸。
- **FR-009**: 系统 MUST 保持现有搜索、分类筛选、加入购物袋、数量增减、删除和合计逻辑；切换社区/普通/官方方案不得清空、重复添加或重置购物袋。
- **FR-010**: 系统 MUST 在演示设置中展示社区库的实际版本与单透镜能力信息；设备 ABI 或 SDK 不满足时，必须显示不可用原因，不能把降级效果标记为接入成功。
- **FR-011**: 系统 MUST 在页面重进、前后台切换和方案切换时正确管理 AppleUI 生命周期；不得重复创建透镜实例，不得让已销毁实例继续截帧。
- **FR-012**: 社区模式 MUST 继续使用白色/浅灰底、深灰文字、绿色强调、真实本地商品图片和现有间距；不得重新引入深色渐变、测试色块、技术介绍卡片或首页模式切换栏。
- **FR-013**: 社区导航 MUST 检查浅色内容上的文字和图标可读性；可读性不足时通过图标/文字颜色或局部小范围处理解决，不得增加覆盖大片商品内容的白色渐变或遮罩。
- **FR-014**: 系统 MUST 在构建、安装、四栏切换、滚动、搜索、分类、购物袋、前后台和页面重进验证中记录实际结果；未运行的项必须明确标注，不得用推测代替测量。
- **FR-015**: 本特性 MUST NOT 修改 `mf_api` 工程，不提交或推送 Git，不增加与 AppleUI 无关的权限或依赖。

### Key Entities *(include if feature involves data)*

- **导航方案**: 普通、官方、社区三种方案；每种方案共享同一套业务页面和购物袋状态，只改变底部导航材质与呈现方式。
- **社区透镜**: 单个 AppleUI 实例，绑定底部导航胶囊的宽高、圆角、模糊和折射参数；不承载商品列表，不承担导航点击。
- **导航入口**: 推荐、分类、购物袋、我的；包含图标、文字、选中态和购物袋数量角标。
- **购物袋状态**: 现有本地内存中的商品行项目、数量、价格与合计；跨方案共享，不因材质切换重建。
- **能力状态**: 设备 ABI、API 版本、AppleUI 版本和渲染可用性；用于设置页说明和最终验收报告。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在支持的 arm64 设备上，社区方案可以从演示设置选中并回到推荐页；底部出现且只出现一个液态玻璃胶囊。
- **SC-002**: 社区导航的四个入口均可点击并切换页面；在玻璃覆盖区域和商品列表区域滚动、点击“加入”、增减数量、删除均无被吞事件。
- **SC-003**: 玻璃采样来自实时商品内容；滚动商品列表时透镜内的背景随内容变化，不出现固定预制动图、固定纹理或截图替代。
- **SC-004**: 社区模式下不出现黑块、青/品红自反馈、明显错位或空效果层；若出现，必须能给出复现条件、日志和修复记录。
- **SC-005**: 在普通、官方、社区之间来回切换至少 3 次，购物袋商品数量、行项目和合计保持不变；页面重进和前后台恢复后不产生重复透镜实例或重复商品。
- **SC-006**: 普通导航和官方导航的现有视觉与交互不因本特性发生回退；三套方案的设置入口都可识别。
- **SC-007**: 构建成功，`arkts_check` 无错误；真机验证覆盖四个导航入口、滚动、搜索、分类筛选、加入购物袋、数量变化、删除、前后台恢复、页面重进和方案切换。
- **SC-008**: 不支持的设备或渲染失败时，设置页或最终报告明确说明原因；不把透明、黑块、默认白底或降级效果计为接入成功。
- **SC-009**: 不新增振动权限，不开启 ProUI/Vibrate，不修改 `mf_api`，不提交或推送；未测量项不写帧率或耗电结论。

## Assumptions

- 现有“米饭好物”业务页面、商品数据、购物袋逻辑和视觉基线保持不变；本特性只新增社区导航包装层和设置入口。
- 目标验证设备为 HUAWEI Pura X（VDE-AL00，API 26，arm64-v8a）；现有环境报告可复用，设备或 SDK 变化时再核对。
- `com.hm.appleui.hw` 2.1.0 是当前最新版，`compatibleSdkVersion` 为 API 20，仅提供 arm64-v8a 原生库；当前工程 target API 24、设备 API 26 满足要求。
- 默认启动方案仍为官方方案；社区方案作为第三个可选项，不改变首屏默认体验。
- AppleUI 的 `Width`、`Height` 单位为 vp；`Circle` 为圆角半径占短边比例；`Blur` 单位为 vp；`NeoStrength` 为无单位折射强度。首轮使用 `Blur = 0`、`NeoStrength` 约 0.20–0.22、`ProUI = false`、`Vibrate = false`。
- 社区透镜宽度按导航胶囊的内容宽度计算，高度与现有导航一致；底部安全区沿用现有页面安全区处理。
- 不支持的 ABI 或渲染条件通过设备 ABI 检查和实际运行结果判断；无法运行时保留普通/官方方案，不制造虚假玻璃效果。
- 验证只记录可观察的界面、日志和交互结果，不对帧率、耗电或 GPU 性能下结论。

## Open Questions

- 无未决的范围内问题；若真机出现 AppleUI 原生渲染失败，按 FR-010、SC-004 和 SC-008 保留复现与日志，不把该次运行计为成功。
