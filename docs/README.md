# 笔记格式约定

## 命名

一个项目对应一份笔记，名字与 `apps/` 下的目录完全同名，**不带序号**：

```
apps/mf_api/          ← 工程源码
docs/mf_api.md        ← 这个项目的报错记录
```

不带序号是有意的：以后插入新 API、调整顺序、删掉某个项目，都不用重命名已有文件。

## 固定结构

```markdown
# mf_api · 网络请求

## 环境
| 项 | 值 |
|---|---|
| DevEco Studio | x.x.x |
| HarmonyOS API | xx |
| 设备 | 真机型号 / 模拟器 |

## 要做什么
一句话说清这个项目干什么用，为什么需要这个 API。

## 第一版代码
第一次跑起来的那版，贴关键文件即可，不用全贴。

## 报错 1：<一句话概括>
**报错原文**
```
（整段日志，含错误码，原样复制）
```
**根因**
**改法**

## 报错 2：...
（同上，2-3 个）

## 最终代码
指向 `apps/mf_api/` 里的具体文件，关键行给注释。

## 边界
什么情况下别用这个 API / 有替代方案吗 / 哪个版本之后行为变了。

## 参考
官方文档链接（回源用）。
```

## 三条纪律

1. **报错原文必须原样复制**，不改写、不省略、不事后补写。含错误码的完整输出才有搜索价值。
2. **想当然的地方要写明**——第一版哪里猜错了、为什么错。这部分比正确代码更有用。
3. **每条报错都标注触发条件**（真机/模拟器、哪个权限没给、哪一步操作后出现的）。没有触发条件的报错，别人复现不了。
